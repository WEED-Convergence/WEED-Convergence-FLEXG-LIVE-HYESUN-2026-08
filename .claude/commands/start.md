CONVERGENCE Docs 저장소의 온보딩을 진행한다. 곧바로 코드를 치지 말고, 루트 `CLAUDE.md`의 **「🚀 온보딩 프로토콜」** 순서를 그대로 따른다.

1. **환경 확인** — `node_modules` 존재 여부를 확인해 없으면 `npm install`을, 실행은 `npm run dev`(http://localhost:3000)를 안내한다. 주요 경로(`/docs`·`/docs/overview`·`/docs/pages`·`/components`)를 한 줄로 알려준다.
2. **"무엇을 하실 건가요?"** — 새 화면 만들기 / 기존 화면 수정 / 컴포넌트 찾기 / 개요·진행상황 보기 중에서 고르게 한다(선택지로 제시).
3. **새 화면이면** — ① 어떤 서비스(FLEXG·발주모아·캐치셀·PAGE)? → ② 어떤 페이지(area)? 를 물은 뒤, 그 서비스+페이지의 **표준 컴포넌트를 `src/design-system` 배럴에서** 가져와 조립을 시작한다. 표준에 없으면 프로토타입 내 임시 조립 + 설명에 「디자인시스템 요청 대상」으로 남긴다(컴포넌트화·갤러리 등록은 하지 않는다).
4. 작업은 **브랜치 + PR** 흐름으로(작업 규칙 9), 색은 그 서비스의 디자인 토큰으로만.

**선택지 작성 규칙 (중요 · 대상은 비개발자)** — 팀원 상당수가 개발 지식이 적다. 모든 선택지의 label·설명은 **비개발자도 바로 아는 쉬운 말**로 쓴다.
- 컴포넌트명·파일명·코드 식별자(예: `AdminLayout`·`Dialog`·`LoginCard`·`src/...`) 절대 넣지 않는다.
- 무엇을 고르면 어떤 결과인지 **행동·화면 기준**으로 한 줄. 예:
  - 페이지: 어드민="운영자가 쓰는 관리자 화면" · 송출앱="방송을 내보내는 앱 화면" · 고객뷰어="고객이 보는 화면" · 샵="쇼핑몰에서 사고파는 앞단 화면"
  - 서비스: 준비중인 것은 "아직 준비중 — 지금은 FLEXG로 시작 권장"처럼 쉽게.

상세 규칙은 `docs/지침.md`를 참고한다. 사용자가 이미 뭘 할지 말했다면 해당 단계로 바로 진입한다.
