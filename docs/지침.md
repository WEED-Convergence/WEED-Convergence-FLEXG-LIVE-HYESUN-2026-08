# CONVERGENCE Docs — 기획 문서 작성 지침

이 포맷(CONVERGENCE Docs)으로 기획 문서를 쓸 때 **매번** 지키는 규칙.
AI용 지침(저장소 루트 `CLAUDE.md`)과 같은 규칙을 공유한다.

---

## 1. 문장 — 명료 선언형

읽는 사람에는 비개발자(디자인·마케팅·영업)도 있다. 짧고 분명하게.

| 규칙 | 나쁜 예 | 좋은 예 |
| --- | --- | --- |
| 줄글 대신 간결 선언형(명사형·"~함") | 고객이 입장하면 닉네임을 물어봅니다. | 입장 시 닉네임을 1회만 등록함 |
| 항목이 여럿이면 `1) 2) 3)`으로 나열 | 카드로 요약하고 클릭하면 상세로 갑니다 | 1) 카드로 요약함<br>2) 클릭 시 상세로 이동함 |
| 코드 식별자·내부 용어 금지 | `state=live`일 때 `LiveSettingsV2` 노출 | 방송 중일 때 설정 화면 노출 |

- 강조(빨강/굵게)는 한 항목에 **1~2곳만**.

## 2. 표 — 가능하면 무조건 표

탭 구성·컬럼·상태별 동작·매핑처럼 **축이 둘 이상**이면 줄글로 풀지 말고 표로.

- 상태(로그인 전/후·권한 등)별 노출·동작 차이는 `stateTable`로 만든다.
- "A일 때 X, B일 때 Y" 식 문장이 2개 이상이면 표로 바꾼다.
- **문서 표는 항상 직사각형**(라운드 없음). 항목이 많을 수 있으니 **내용은 셀로 분리**해 쓴다(한 셀에 몰아넣지 않음).

```
✕  관리자는 저장 가능, 운영자는 읽기 전용
○  | 권한   | 저장         |
   | 관리자 | O            |
   | 운영자 | X (읽기전용) |
```

## 3. 설명 — 기능 정의·예외 케이스 (컴포넌트는 분리)

설명 패널의 섹션 `body`에는 **그 프로토타입의 기능 정의·규칙·예외 케이스**를 쓴다.
무엇을 하고, 언제 어떻게 다르게 동작하는지 — **개발·디자인 협업에 필요한 것**을 담는다.

- 컴포넌트명·색·px 같은 **구현 디테일은 body에 쓰지 않는다.**
- 화면에 실제 쓴 표준 컴포넌트명은 `components: [...]`로 **분리** → 각 섹션 아래 「사용된 컴포넌트」로 묶여 노출된다.
- 표준 컴포넌트 없이 임시 조립한 영역은 body에 「표준 컴포넌트 미적용 — 디자인시스템 요청 대상」으로 남긴다. (프로토타입은 조립만; 컴포넌트화·갤러리 등록은 디자인시스템 트랙의 일)

```
✕  body: 주문 상태별 건수를 지표 카드(StatCard)로 나열함
○  body: 1) 주문 상태별 처리 필요 건수를 요약
        예외) 처리할 건이 없으면 0으로 표기(숨기지 않음)
   components: ['SectionHead', 'StatCard']
```

## 4. 마커 — 화면과 설명 1:1

- 화면 요소에 `data-doc-mark="키"`, 설명 섹션에 `mark:"키"`를 달아 번호로 잇는다.
- 번호는 화면 좌표(**위→아래**) 순으로 자동 매겨진다.
- 마커는 요소의 **왼쪽 위 모서리**에 **원형**으로 붙는다(마커=분홍, 코멘트 핀=파랑).
- 마커로 못 찍는 개요·전제·공통 규칙은 **공통(common) 영역**에 쓴다(탭 무관 항상 노출).

## 5. 공통 영역 필수

- 새 화면은 항상 **공통 개요(common)** + 구역별 마커 섹션을 갖춘다.
- 공통엔 화면 전체 전제·구성·상태 규칙을 `1) 2)`로 적는다.

## 6. 변경 프레이밍 금지

확정 배포(핸드오버)된 것 외에는 이전 버전 대조로 쓰지 않는다.

- `기존 A를 B로 개편/변경` ✕ → 그 화면의 스펙을 **현재형**으로 서술 ○
- 이 포맷엔 배포월/릴리즈/변경종류 개념이 없다. 화면의 진행도는 `status`(작성중/검토중/확정)로만 표기 → 「작업페이지 한눈에 보기」에 반영.

## 7. 기타

- UI에 **이모지 금지** — SVG 아이콘 컴포넌트로.
- 색상·간격·개발 URL 등 디자인/구현 디테일은 설명에 쓰지 않는다(동작만 서술).
- 페이지를 수정하면 `updatedAt`(변경일)을 **수정한 날짜**로 갱신한다.
